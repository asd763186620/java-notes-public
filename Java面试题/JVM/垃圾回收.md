# 什么是垃圾回收
主要针对于堆中存放的对象和数组等。

# 为什么需要垃圾回收
如果堆中无限制的创建对象，不销毁，则迟早会导致OOM内存溢出。

# 对象什么时候可以被垃圾回收器回收
如果一个对象或多个对象没有任何的引用指向它，那么这个对象就是垃圾，如果定为了垃圾，则可能会被垃圾回收器回收。

如果要定位什么是垃圾有两种方式：引用计数法，可达性分析算法

# 定位垃圾的算法
1. 引用计数法：一个对象被引用一次，在其对象头上会进行引用次数递增，如果对象的引用次数为0，则这个对象可回收<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778660565130-e25b0b25-b1d1-4f02-aed1-3a14ea6102d1.png)循环引用导致内存泄露（申请了内存空间最终没有释放白白占有资源），最后导致内存溢出
2. 可达性分析算法：通过gc root通过链时结构，引用对象，如果通过引用链找不到对象则对象可以回收。
    1. java虚拟机的垃圾回收器通过可达性分析来探索所有存活的对象
    2. 扫描堆中的对象，如果通过gc root根为起点的引用链可以找到该对象则存活，如果找不到则就是垃圾可以回收<!-- 这是一张图片，ocr 内容为： -->

# 垃圾回收的算法
## 标记清除算法
1. 根据可达性算法得出的垃圾进行标记
2. 对这些标记为垃圾的可回收的内容进行垃圾回收
3. 优点：标记和清除速度较快
4. 缺点：碎片化严重，内存不连贯

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778661328989-4bf394ac-6250-467e-8fcb-a4f8387e6893.png)

## 标记整理算法（老年代）
1. 根据可达性算法得出的垃圾进行标记
2. 对这些标记为垃圾的可回收的内容进行垃圾回收
3. 整理碎片空间 ，将存活对象向内存另一边移动，清理边界以外的垃圾对象
4. 优点：标记和清楚速度较快（比标记清除算法慢），解决了标记清除碎片化问题
5. 缺点：比标记清除算法多了一步整理内存位置，效率收到影响

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778661458473-356a46ec-2583-45a1-add4-fbfc8e63f2f0.png)

## 标记复制算法（新生代）
1. 内存分为两块，每次用一块
2. 通过可达性算法标记垃圾
3. 将不是垃圾的对象放到另外一块内存空间同时清除垃圾对象
4. 优点：垃圾对象多时效率高，清理后内存无碎片
5. 缺点：需要两块内存空间，同一时刻只能用一半，内存使用率低

## 内存划分
<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778662074169-f3a41448-b401-4d96-b7e7-e320256a2477.png)

## 工作机制
1. 初始化时，创建一个新的对象分配到伊甸园区
2. 当伊甸园区满时，会通过标记伊甸园区和幸存者一区的存活对象
3. 将存活对象从伊甸园区和幸存者一区复制到幸存者二区，回收垃圾对象释放内存
4. 当伊甸园区再次满时，再次通过标记复制算法，将伊甸园区和幸存者二区中的存活对象放入幸存者一区，回收垃圾对象释放内存
5. 当幸存者区域的对象在gc垃圾回收下存活多次（最多十五次时），会将其放入老年代（当幸存者内存不足或大对象会导致提前晋升）

## MinorGC、MixedGC、FullGC区别是什么
1. MinorGC发生在新生代的垃圾回收，暂停时间短（STW-stop the world）
2. MinxedGC新生代和部分老年代的垃圾回收，G1收集器特有
3. FullGC：新生代+老年代完整的垃圾回收，暂停时间长，应尽力避免

# JVM有那些垃圾回收器
<!-- 这是一张图片，ocr 内容为： -->

1. 串行垃圾回收器
2. 并行垃圾回收器
3. 并发垃圾回收器
4. G1垃圾回收器

## 串行垃圾回收器
serial和serial old 串行垃圾回收器，使用单线程进行垃圾回收，堆内存小

serial：作用于新生代使用复制算法

serial old：作用于老年代使用标记-整理算法

垃圾回收时只有一个线程工作其余线程阻塞等待

## 并行垃圾回收器
parallel new 和 parallel old 并行垃圾回收器，jdk8默认垃圾回收器

parallel new ：作用于新生代使用复制算法

parallel old：作用于老年代使用标记-整理算法

垃圾回收时，多个线程同时工作，垃圾回收线程之外的所有线程也要暂停等待垃圾回收完成

## CMS并发垃圾回收器
全称：concurrent mark sweep，是一款并发的、使用标记-清除的垃圾回收器，该回收器是针对老年代垃圾回收的，是一款以获取最短回收停顿时间为目标的回收器，停顿时间短，体验好，最大特点是在进行垃圾回收时，应用仍然可以正常运行。

## G1垃圾回收器
### 概念
1. 适用范围：新生代和老年代都适用，模糊了物理内存的分代概念，但是逻辑分代仍然存在。
2. 划分为了多个内存区域，每个区域都可以是伊甸园区、幸存者区、老年代以及一个新的概念大对象（如果一个对象过大一块内存区域不足，就会开辟一块连续的内存区域存储大对象）。
3. 回收算法采用标记复制算法。
4. G1垃圾回收器兼顾了响应时间和吞吐量
5. 在G1垃圾回收器工作时分为了三个阶段（新生代回收、并发标记、混合收集）
6. 如果并发失败（垃圾回收速度跟不上创建新对象的速度），则会出发FullGC
7. <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778835106185-27c0acb0-f63e-4778-8149-4a3827dd346d.png)

### 工作流程
1. 阶段一：年轻代垃圾回收
+ 初始时，所有的区域都是空闲状态
+ 当创建对象时，会随机分配一块内存区域作为伊甸园区存放对象（占比5%-6%波动G1自动调整）
+ 当伊甸园满时，会出发垃圾回收，将标记的存活对象，在随机选择一块区域作为幸存者区，将伊甸园区存活的对象通过标记复制算法复制到幸存者区，同时进行回收伊甸园区的垃圾对象，此操作（标记复制算法执行时）需要暂停用户线程（STW）。
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778835525311-edeb7cfb-0f42-47db-8d89-0f66517386d2.png)
2. 年轻代垃圾回收+并发标记+重新标记
+ 随着时间增长，当伊甸园区的内存再次不足时
+ 会再次通过标记复制算法，将伊甸园区和幸存者区存活的对象再次复制到新的幸存者区，同时如果幸存者区存在多次存活的对象到了升代阈值，会开辟一个新的区域做为老年代存放多次存活的对象。对年轻代进行垃圾回收。
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778835795301-4a3932d5-5538-49f5-89eb-ca1412518655.png)
+ 当老年代占有内存超过阈值（默认45%）后，会触发并发标记，此时无需暂停用户线程
+ 重新标记存活对象，处理漏标的对象，此时仍然会触发STW
+ 此时并发标记和重新标记都完成之后，就会确定老年代有哪些存活对象了，随后进入混合垃圾回收阶段。
3. 混合垃圾回收阶段
+ 此时并不会对所有的老年代进行垃圾回收，而是根据暂停时间（可设置），优先回收价值高的区域（存活对象少，能释放更多内存的区域）。
+ 此阶段会将年轻代中的伊甸园区和幸存者区也进行标记复制算法，将标记存活的对象复制到一个新的幸存者区中。同时将选择出来的回收价值高的老年代也复制到一块新的内存区域，然后释放内存，此阶段也会进行STW，此回收老年代的操作可能进行多次将老年代内存逐渐释放。
+ 此阶段结束之后就会进行下一轮的新生代回收、并发标记、混合垃圾回收
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778836298225-135a925c-8b96-4d09-8083-f718e889eee1.png)
4. 异常情况
+ 如果垃圾回收的速度跟不上创建新对象的速度，此时出现并发失败，会触发一次FullGC此时暂停时间就长了，应尽量避免
+ 如果存在一个大的对象一块内存区域无法存放会开辟一块连续的内存空间存放大对象。

# 强、弱、软、虚引用的区别
1. 强引用
+ 只有GC Roots对象都不引用该对象，该对象才能别垃圾回收
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778837340058-ac33b612-0c91-4940-a08b-c6d7ec06aef4.png)
2. 软引用
+ 仅有软引用引用该对象时，在垃圾回收后，内存不足时会再次触发垃圾回收，此时会回收软引用对象
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778837366044-3b35e6b9-146e-45e7-a35a-98038441b3e5.png)
3. 弱引用
+ 仅有弱引用引用该对象时，只要进行垃圾回收，无论内存是否充足都会回收弱引用对象
+ <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778837403727-1f6324df-4e84-44f3-a596-ce1feab32a9a.png)
4. 虚引用
+ 必须配合引用队列使用，被引用对象回收时，将虚引用入队，由Reference Handler线程调用虚引用相关方法释放直接内存。（不在堆中在直接内存中（直接内存是操作系统单独开辟出来一块内存由jvm管控））
