# JVM运行流程
由程序员编写的.java代码通过java编译器编译成.class的二进制字节码文件

然后经过类加载器将二进制字节码文件加载到内存

再由解释器、及时编辑器将字节码文件翻译成底层系统指令

通过垃圾回收器管理内存

再由c和c++实现的本地方法接口和本地库执行java代码执行不了的系统底层指令

# 程序计数器（PC Register）
程序计数器时线程私有的，每个线程有自己的一份，内部保存了字节码的行号，用于记录正在执行的字节码指令的地址。

如图所示：如果第一次线程1执行时，从0行执行到了第十行时，丢失了代码执行权，由线程2得到了cpu指令去执行，此时线程1的程序计数器会将执行到的第10行记录下来，然后线程2执行，从0行执行到了第9行，然后cpu再次分配指令给线程1，此时线程1从内部程序计数器记录的第10行开始执行，同理如果有cpu将执行权赋给线程2执行时，也是从线程2内部的程序记录器记录的第九行开始。

## 大白话解答
程序计数器是jvm运行时数据区中一块线程私有的区域，用于存储当前线程正在执行的字节码指令的地址，java是多线程执行的，因此需要知道每个线程自己的执行地址才能在cpu进行切片时，获得cpu执行权时知道自己到底执行到了什么位置。

执行java方法时，记录的是字节码指令的地址。执行native方法时值通常是undefined。也是在jvm中规定没有oom的区域。

程序计数器是线程私有的，如果不是私有的话会导致，java在多线程环境下执行时，如果进行了cpu切片，线程再次获得cpu执行权时，不知道该从哪里执行，会出现重复执行，漏执行和执行流程混乱的问题，导致程序出现异常，因此每个线程都需要维护自己私有的一个程序计数器。

程序计数器在jvm规范中没有规定此区域会抛出oom，因为只存储了一小块字节码指令地址，不会像堆一样不断创建对象，也不会像栈一样重复压入栈帧，会随着线程执行完毕后一起销毁。

# 堆
## 概念
堆：是线程共享的区域，用于保存实例对象和数组等，内存不够的话则抛出内存溢出异常

## 堆组成：
1. 新生代（eden区和两个大小严格相同的survivor区）
    1. 伊甸园区（占有新生代内存比例8）
    2. 幸存者1区 （占有新生代内存比例1）
    3. 幸存者2区（占有新生代内存比例1）
2. 老年代（保存生命周期长的对象）
3. 新生代和老年代占有内存大小1:2

## 执行过程：
当创建一个对象时，会存入新生代的伊甸园区，如果进行GC之后还存在则会进入幸存者区，如果多次GC对象仍然存在就会存放到老年代

## jdk1.7和1.8区别
jdk1.7的堆中有永久代用于存放类信息，常量、静态变量、编译后的代码等。

jdk1.8之后取消了永久代将永久代中存放的信息放入了本地内存的元空间中，防止内存溢出。

# 虚拟机栈Java Virtual machine stacks
## 概念
1. 虚拟机栈是线程私有的，每个线程有自己独立的虚拟机栈
2. 虚拟机栈指的是每个线程运行时，所需要的内存，先进后出
3. 内部由多个栈帧组成，对应这每个方法调用时所占用的内存（栈帧存储了方法的参数，局部变量和返回值）
4. 每个虚拟机栈只有一个活动栈帧对应正在行的某个方法

## 执行流程
当前如果有三个方法ABC，

A调用B，B调用C

此时A先入栈然后执行B，B入栈，B调用C，此时C入栈，C执行完毕时出栈然后B执行完毕出栈最后A执行完毕出栈。

## 是否会发生GC
虚拟机栈中不会发生垃圾回收，垃圾回收主要针对于堆中的对象，因为虚拟机栈中的栈帧会随着方法的执行完毕进行弹栈释放内存。

## 虚拟机栈是否需要分配大的内存
虚拟机栈中栈内存默认是1024k，如果栈过大会导致线程数变少，例如机器内存是512m，此时最大能活动的线程数为512个，如果设置为2048会导致，能活动的栈帧减半

## 方法内部的局部变量是否线程安全
如果方法内部的局部变量只在方法内部使用则是线程安全的。

如果方法内部的局部变量是参数或者返回值，此时此变量可能也会被其他的线程操纵。此时就不是线程安全的了

## 栈内存溢出情况
栈帧过多导致的内存溢出，例如死循环的递归调用

栈帧过大导致内存溢出，例如局部变量定义过大占用内存过大，栈默认为1024k如果定义一个超过此大小的局部变量就会导致栈内存溢出

# 堆栈区别
1. 栈内存是线程私有的，堆内存是线程共有的
2. 堆中存储实例对象和数组等，栈中存储方法调用和局部变量
3. 堆中的对象会被GC垃圾回收，而栈中的栈帧在方法执行完毕之后弹栈释放内存
4. 堆内存溢出报异常为oom，栈内存溢出报sof

# 方法区Method Area
1. 线程共享的区域
2. 存储类信息、运行时常量池
3. 虚拟机启动时创建，关闭虚拟机时释放
4. 如果方法区内内存无法满足时，会抛出00M（Metaspace）异常

# 常量池
可以看作为一张表，虚拟机指令可以根据这张常量表找到要执行的类名、方法名、参数类型、字面量（源码中写下的无需计算即可知道含义的常量值）等信息

# 运行时常量池
常量池是.class文件中的，当类被加载，常量池信息就会放入运行时常量池，并把里面的符号地址变为真实内存地址

# 直接内存
直接内存并不属于jvm的内存结构，不由jvm管理，是虚拟机的系统内存

常见于nio操作时，作为数据缓冲区，分配回收成本高，但是读写性能高， 不受jvm内存回收管理。
