# 什么是类加载器
 jvm只会运行二进制文件，类加载器的作用就是将字节码文件加载到jvm中，从而让java程序启动

## 启动类加载器，c++实现
加载java核心类库目录：jre/lib

## 扩展类加载器
加载扩展目录各种jar包jre/lib/ext

## 应用类加载器（默认加载器）
加载开发者自己编写的java类

## 自定义类加载器（用得不多）
实现自定义的类加载器，可以自定义加载规则

# 双亲委派模型
加载某一个类，会先委托上级加载器进行加载，如果上级加载器还有上级，就会继续向上委托，如果没有委托的上级加载器加载，那么则自己尝试加载该类。

示例1：

自定义一个类Student，去加载此类时，会通过应用加载器，而应用加载器有上级扩展类加载器，因此会去委托扩展类加载器加载，扩展类加载器还有上级启动类加载，那么就会在去委托启动类加载器，启动类加载器一看自己负责的目录jre/lib下没有此类，则会告知扩展类加载器，扩展类加载器会在jre/lib/ext下看是否有此类，结果也没有则会通知应用类加载器，此时应用类加载器就会尝试加载此类

示例2：

加载String类，应用--扩展--启动--找到String直接加载直接返回应用加载告知可以使用

# 为何使用双亲委派机制
1. 避免某一个类，被加载器重复加载，当父类加载器加载后无需重复加载，直接使用，保证唯一性
2. 为了安全，防止篡改系统api，保证系统类库api不被修改

# 类装载的执行过程
类从加载到虚拟机中开始，直到卸载生命周期为：加载、验证、准备、解析、初始化、使用、卸载

验证、准备、解析三部分统称为连接。

<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778658486540-672c6d2a-aa08-45cb-9dca-9dc092fc8bee.png)

1. 加载（查找和导入class文件）
    1. 通过类的全名获取类的二进制数据流
    2. 解析类的二进制流为元空间（方法区）内的数据结构（java类模型--构造函数-方法-属性等）
    3. 创建java.lang.Class类实例，表示该类型，作为元空间（方法区）这个类的各种数据的访问入口
    4. <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778658785576-3146842b-93e6-4ccb-9939-437ddcf35c70.png)
2. 验证（保证加载类的准确性）
    1. 验证类是否符合JVM规范，安全性检查
    2. 文件格式验证
    3. 元数据验证
    4. 字节码验证
    5. 符号引用验证--Class文件在其常量池中会通过字符串记录自己需要使用的类或方法，检查是否存在<!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778658885001-268f0cd1-3d77-46d8-8600-b592170ebe9b.png)
3. 准备（为类变量分配内存和设置类变量初始值）
    1. 为类变量分配内存并设置类变量初始值
    2. static修饰的变量，分配空间会在此准备 阶段设置默认值，真正赋值在初始化阶段
    3. static修饰的final变量和字符串会在此准备阶段直接赋值
    4. static修饰的final应用数据类型，其真正赋值也在初始化阶段
4. 解析（把类中的符号引用改为直接应用）
    1. 将类中的符号引用转换为直接引用
    2. 字节码文件通过#数字记录了对应的引用（在常量池中记录了对应的类名、方法名等）
    3. 解析变成直接引用就是通过指针直接执行对应类的对应方法
    4. <!-- 这是一张图片，ocr 内容为： -->
![](https://cdn.nlark.com/yuque/0/2026/png/43313275/1778659506992-a3c55ea3-7151-41d1-a9ce-852aee4f0e37.png)
5. 初始化（对类的静态变量、静态代码块执行初始化操作）
    1. 对类的静态变量、静态代码块执行初始化操作
    2. 如果初始化一个类时，其父类未初始化，则优先初始化其父类
    3. 如果同时包含多个静态变量和静态代码块，则按照自上而下顺序一次进行
    4. 如果子类使用父类的静态变量，此时只会初始化父类不会初始化子类
6. 使用（jvm开始从入口方法执行用户的程序代码）
    1. jvm开始从入口方法开始执行用户的程序代码
    2. 调用静态类成员信息（静态变量、静态代码块）
    3. 使用new关键字为其创建对象
7. 卸载（用户程序执行完毕，jvm销毁创建的class对象）
    1. 程序代码执行完毕jvm销毁创建的class对象
    2. 此时代表卸载了
