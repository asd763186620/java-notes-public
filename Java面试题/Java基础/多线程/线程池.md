# 线程池核心参数
1. 核心线程数：执行任务的线程
2. 最大线程：核心线程数+临时救济线程，无空闲的核心线程，并且阻塞队列已满，创建临时线程执行， 没有活跃任务并且生存时间到期销毁临时线程
3. 阻塞队列：无空闲核心线程时，新的任务放入阻塞队列，阻塞队列满，创建临时线程执行任务
4. 生存时间：临时线程生存时间
5. 生存时间单位：秒、毫秒等
6. 线程池工厂：设置线程名称，设置是否是守护线程等
7. 拒绝策略：直接抛出异常（默认）、利用当前调用线程执行（主线程执行）、丢弃阻塞队列中靠前的任务执行当前任务、直接丢弃任务

# 线程池执行原理
![画板](https://cdn.nlark.com/yuque/0/2026/jpeg/43313275/1777338274652-7cf718f7-350e-42eb-92ff-53238e1c31e9.jpeg)

1. 设置线程池参数核心2、最大3、队列2、生存时间0、单位秒、拒绝策略1
2. 提交两个等待1小的任务
3. 提交任务3则会检查阻塞队列是否已满
4. 当前阻塞队列中无任务，将当前任务3添加入队列
5. 提交任务4，再次检查阻塞队列是否满
6. 当前阻塞队列长度设置的是2，已经有任务3，将任务4添加入队列
7. 提交任务5，检查阻塞队列是否已满
8. 阻塞队列长度为2，已经有任务3和4
9. 创建临时线程执行任务5，如果此时任务5不需耗时，则执行完毕5之后执行3、4
10. 如果任务5也需长时间，则此时任务3、4继续等待
11. 提交任务6，此时队列满，无空闲核心线程，任务5被临时线程执行，此时根据拒绝策略执行
    1. 、AbortPolicy：直接抛出异常，默认策略
    2. CallerRunsPolicy：用调用者所在的线程执行任务（主线程执行）
    3. DiscardOldPolicy：丢弃阻塞队列中最靠前的任务，将当前任务添加到队列
    4. DiscardPolicy：直接丢弃当前任务

# 线程池常见的阻塞队列
## ArrayBlockingQueue：基于数组结构的有界阻塞队列，FIFO（先进先出）
1. 底层数据结构数组
2. 强制有界（定义容量）
3. 提前初始化的数组，Node提前创建好
4. 一把锁锁数组

## LinkedBlockingQueue：基于链表结构的有界阻塞队列，FIFO
1. 底层数据结构单向链表
2. 可以有界可以无界（不给定初始容量时，代码内部使用的是int最大值最为容量）
3. 懒加载，创建节点的时候添加数据，入队生成新的Node
4. 两把锁，头节点和尾节点上锁

## DelayedWorkQueue：优先级队列，保证每次出队的任务都是当前队列中执行时间最靠前的
## SynchronousQueue：不存储元素的阻塞队列，每个插入操作都必须等待一个移除操作（一手交钱一手交货）
