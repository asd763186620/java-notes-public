# 什么是事务，事务的特性
## 概念
事务是一组操作的集合，是一组不可分割的工作单位，事务会将所有的操作作为一个整体向数据库系统进行提交或回滚操作，要么一起成功要么一起失败。

## 特性
1. A：原子性Atomicity-事务是不可分割的最小操作单元，要么一起成功要么一起失败
2. C：一致性Consistency-事务完成时，使所有数据保持一致状态
3. I：隔离性Lsolation-数据库系统提供隔离机制，事务在运行时，不受外部并发操作的影响，在独立的环境下运行。
4. D：持久性Durability-事务提交或者回滚之后，对数据库中数据的改变是永久的。

# 并发事务以及隔离机制
## 并发事务分类
1. 脏读：一个事务读取到了另外一个事务未提交的数据
+ 例如事务一查询id为1的数据时并且将其修改，但是还未提交时，被另外一个事务查询到了
2. 不可重复读：在同一个事务中先后查询同一条数据，发现数据不同
+ 例如事务一有三条操作查询id为1的数据，查询id为2的数据再次查询id为1的数据，结果操作一和操作三的查询结果不一致，被其他事务所修改提交了，此时为不可重复读
3. 幻读：在同一事务中进行查询添加操作，查询不到去添加时又发现此数据已存在。
+ 例如事务一有三个操作，操作一查询di为1的数据，然后不存在的话进行添加数据，但是添加失败，再次查询还是不存在对应数据。在事务一进行时，事务二进行了添加操作。但是事务一未读取到。

## 隔离级别
事务隔离级别越高，数据越安全，性能越低，平衡安全和性能之后MySQL默认隔离级别为可重复读。

1. 读未提交：可以读到其他事务未提交的数据
+ 无法解决脏读、不可重复读、幻读
2. 读已提交：只能读到其他事务已经提交的数据
+ 可解决脏读，无法解决不可重复读和幻读
3. 可重复读：同一事务内读取同一批数据，结果保持一致<font style="color:#DF2A3F;">MySQL默认隔离级别</font>
+ 可解决脏读、不可重复读无法解决幻读
4. 串行化：事务一个个执行，同一时间只能有一个事务执行
+ 可解决脏读、不可重复读、幻读

# undo log 和 redo log 区别
## 缓冲池
MySQL的内存结构，内存缓冲池，主内存的一块区域通过读取磁盘数据页加载到内存，通过操作内存修改数据，在通过一定频率刷新到磁盘，减少磁盘io加快处理速度

## 数据页
MySQL存储引擎InnoDB管理的最小磁盘单元，每个页默认大小16kb，页中存储了行数据

## redo log
**概念：**

重做日志，记录的是事务提交时数据页的物理修改，用来实现事物的持久性

该日志有两部分组成，内存中有一部分重做日志缓冲以及磁盘中的重做日志文件。当事务进行提交时，将所有修改信息存储到日志文件中，当刷新脏页到磁盘中出现错误时，进行数据恢复使用。

当从内存写入到磁盘进行同步，出现错误，可以从日志文件进行恢复。

日志文件有两份循环写，日志文件是追加顺序的磁盘io。

如果正常的情况下日志无作用，mysql定期清理，主要用于宕机之后的数据恢复。

刷新脏页数据到磁盘时，出现错误可以使用redo log进行恢复，实现数据持久性

## undo log
**概念：**

回滚日志，用于记录数据被修改前的信息，提供回滚、MVCC多版本并发控制，undo log是逻辑日志。

+ 可以认为当进行一条delete操作时，会在undo log中记录一条insert记录
+ 当进行update操作时，会记录一条相反的update记录。当执行rollback时，可以从undo log中读取相应的记录进行回滚。
+ 例如delete from user where id = 1;会记录一条insert into user(id，name，age) values (1,'张三',18);
+ update user set name = '李四' where id = 1;undo log 会记录一条 update user set name = '张三' where id = 1;

实现了事务的原子性和一致性

## 小总结
redo log 重做日志主要作用是保证持久性，MySQL修改数据时不会直接将数据页刷新到磁盘，而是先写日志redo log，事务提交时，只要日志写入成功，即时数据库宕机也能通过redo log进行恢复。

undo log 回滚日志，执行修改操作前会记录修改前的数据，如果事务需要回滚使用undo log 将数据恢复成未修改前的样子，并且基于修改前的数据快照解决了，不可重复读的问题，可以重复读取到快照中的数据，即时数据被其他事务修改了，支持了MVCC并发控制。

# MVCC 多版本并发控制
## 概念
多版本并发控制，维护一个数据的多个版本，使得读写操作没有冲突

## 实现原理
### 数据表中记录的隐藏字段
1. DB_TRX_ID:最新修改的事务id，记录插入或者最后修改这条记录的事务id
2. DB_ROLL_PTR:回滚指针，指向这条记录的上一版本，用于配合undo log指向上一个版本
3. DB_ROW_ID:隐藏主键，如果表中没有主键id，那么会生成该隐藏字段

### undo log
进行insert、update、delete操作的时候，会产生记录事务版本偏于数据回滚的日志

insert操作，产生的日志只在回滚时需要，事务提交后，可以立刻删除

update、delete操作的时候，产生的undo log 日志不仅在回滚的时候需要，在MVCC版本访问也需要，不会立即删除。

### undo log 版本链
多个事务对同一条数据进行操作时，会记录该数据操作的undo log日志生成一条记录版本链条，头部是最新的版本记录，尾部是最早的版本记录

### readview
+ readview（读视图）快照读SQL执行时MVCC提供数据的依据，记录维护系统当前活跃的事务id（未提交的事务）
+ 当前读
    - 读取的是记录的最新版本，读取时会加锁保证不会有被其他事务进行修改。例如：直接select * from user此时，会在表加入共享锁不影响其他事务的操作，如果是select * from user for update、insert、update、delete操作时，使用的排它锁，其余事务不能对当前记录进行操作。
+ 快照读
    - 简单的select查询操作，就是快照读，读取的是记录数据的可见版本，可能是历史数据，不加锁，非阻塞读。
    - read committed：读已提交-每次select 操作都会生成一份快照读
    - repeatable read：可重复读-开始事务后第一个select查询语句会生成快照读，同一事务后面的查询复用
+ readview核心字段
    - m_ids：当前活跃的事务id集合
    - min_trx_id：最小活跃事务
    - max_trx_id：预分配事务id，当前最大活跃事务id + 1
    - creator_trx_id：readview快照视图创建者的事务id
+ readview版本链数据访问规则

## 小总结
MVCC维护一个数据记录的多个版本，使其读写操作没有冲突，通过隐藏字段自增的事务id和记录上一个事务版本的回滚指针，以及通过undo log回滚日志存储对应事务操作的版本历史数据，并且将历史数据根据操作的时间先后，通过回滚指针形成一个链表，最后通过readview解决事务选择版本问题，通过匹配规则和当前创建事务id具体需要访问那个回滚指针对应的事务版本数据。并且不同隔离级别生成的readview快照读是不一样的。可重复读在每次执行查询操作时，都会生成对应的readview，而可重复读只在事务内的第一次查询生成对应的readview，之后的查询复用第一次的readview。
